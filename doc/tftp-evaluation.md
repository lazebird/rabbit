# Rust TFTP 库选型评估

## 1. 评估背景

Rabbit 项目需要实现 TFTP 服务端和客户端功能，用于文件传输。

### 1.1 性能要求

| 要求 | 说明 |
|------|------|
| 异步文件 I/O | 协议请求和文件读写需要异步进行，避免阻塞 |
| 缓存支持 | 文件读写需要通过缓存提高速度 |
| 高吞吐量 | 充分利用网络带宽，减少等待延迟 |

### 1.2 技术原理

**异步文件 I/O 优势：**
- 网络传输与磁盘 I/O 并行执行
- 单线程可处理多连接，无需线程切换开销
- 避免阻塞事件循环，保持高响应性

**缓存机制作用：**
- 预读缓存：提前读取后续块，减少磁盘寻址延迟
- 写入缓存：批量写入磁盘，减少 I/O 次数
- 块对齐：与 TFTP 块大小匹配，减少内存拷贝

## 3. 详细评估

### 3.1 async-tftp

| 维度 | 说明 |
|------|------|
| **定位** | 异步 TFTP 服务端 + 客户端 |
| **协议支持** | RFC 1350 + 2347/2348/2349/7440 扩展 |
| **异步模式** | async，执行器无关（smol 构建） |
| **异步文件 I/O** | ✅ 原生异步，支持 async-io |
| **缓存机制** | ⚠️ 依赖 bytes crate，可通过自定义 Handler 实现 |
| **性能特性** | 块号回绕支持大文件、可配置超时和块大小、RFC 7440 窗口大小 |
| **许可证** | Apache-2.0 / MIT |
| **下载量** | 143,008 |
| **最后更新** | 2025-12-02 |
| **维护状态** | ⚠️ 活跃 |

**优势：**
- 真正的异步实现，网络与文件 I/O 并行
- 执行器无关，兼容 Tokio/async-std/smol
- 支持自定义 Handler，可实现高级缓存策略
- 支持窗口大小扩展（RFC 7440），显著提升吞吐量

**缓存实现方式：**
- 实现 `Handler` trait 自定义读写逻辑
- 可集成 `tokio::fs` 或 `smol::fs` 进行异步文件操作
- 可在 Handler 中实现预读/写入缓存

**适用场景：** 高性能异步场景首选

### 3.3 tftpd (rs-tftpd)

| 维度 | 说明 |
|------|------|
| **定位** | 完整 TFTP 服务端 + 客户端 |
| **协议支持** | RFC 1350 + 块大小/超时/窗口大小扩展 |
| **异步模式** | 多线程 |
| **异步文件 I/O** | ⚠️ 线程隔离，每连接独立线程 |
| **缓存机制** | ⚠️ 通过块大小配置间接实现 |
| **安全特性** | 禁止外部文件访问，限制在指定目录内 |
| **许可证** | MIT |
| **下载量** | 95,661 |
| **最后更新** | 2026-04-01 |
| **维护状态** | ✅ 活跃维护 |

**优势：**
- 功能完整，服务端和客户端一体化
- 支持协议扩展（块大小、超时、窗口）
- 安全设计，防止目录遍历攻击
- 提供命令行工具，可直接使用

**劣势：**
- 多线程模型：文件 I/O 阻塞线程，高并发时资源消耗大
- 不支持真正的异步文件 I/O
- 缓存能力有限，依赖块大小配置

**适用场景：** 功能完整优先、并发要求不高的场景

## 5. 选型结论

### 5.1 推荐方案

| 需求场景 | 推荐库 | 理由 |
|---------|--------|------|
| **高性能异步（推荐）** | **async-tftp** | 原生异步文件 I/O、窗口扩展支持、下载量最高、可自定义缓存 Handler |
| **功能完整 + 活跃维护** | tftpd | 服务端+客户端一体、协议扩展完善、维护最活跃（2026-04-01 更新） |
| **仅需客户端** | tftp_client | 轻量客户端、近期有更新 |
| **嵌入式 / no-std** | ttftp | 零依赖、no-alloc、可自定义 I/O 和缓存 |
| ~~Tokio 生态~~ | ~~tftp-rs~~ | 刚发布待观察 |
| ~~仅需服务端~~ | ~~libtftp~~ | 已废弃（2018年停更） |

### 5.2 项目选型

**Rabbit 项目选择：async-tftp**

| 指标 | 说明 |
|------|------|
| 异步文件 I/O | ✅ 原生支持，网络与磁盘并行 |
| 缓存扩展 | ✅ 通过 Handler trait 可实现预读/写入缓存 |
| 窗口扩展 | ✅ RFC 7440 支持，显著提升吞吐量 |
| 功能覆盖 | 服务端 + 客户端 |
| 运行时兼容 | Tokio / async-std / smol 均可 |
| 下载量 | 143,008（最高） |
| 维护状态 | 活跃（2025-12-02 更新） |

### 5.3 缓存实现方案

使用 async-tftp 时，可通过自定义 Handler 实现缓存：

```
┌─────────────────────────────────────────────────┐
│                  TFTP Handler                    │
├─────────────────────────────────────────────────┤
│  预读缓存（下载）                                  │
│  - 收到 RRQ 后异步预读 N 块到内存                   │
│  - 网络发送与磁盘读取并行                          │
│  - 缓存大小 = 块大小 × 预读块数                    │
├─────────────────────────────────────────────────┤
│  写入缓存（上传）                                  │
│  - 收到数据块后写入内存缓存                        │
│  - 缓存满或传输完成时批量写入磁盘                   │
│  - 减少磁盘 I/O 次数                              │
└─────────────────────────────────────────────────┘
```

### 5.4 集成方式

| 组件 | 方案 |
|------|------|
| 运行时 | Tokio（项目统一使用） |
| TFTP 核心 | async-tftp 库 |
| 缓存 Handler | 自定义实现，集成 tokio::fs |
| 配置选项 | 块大小、超时、窗口大小、缓存大小 |
